# 0.6.0 - Señales de bloqueo y mantenimiento / Blocked signals and maintenance

## Español

### Objetivo

Detectar sesiones Codex que merecen revisión y permitir un mantenimiento
periódico sin crear un servicio residente propio.

### Implementación

- Conserva el último evento terminal de cada sesión: `task_started`,
  `task_complete` o `turn_aborted`.
- Señala solamente sesiones activas cuyo último evento es `task_started`, sin
  cierre posterior y con una inactividad superior a `blocked_after_hours`.
- Añade el informe `blocked` y el ciclo único `maintain`.
- `maintain` actualiza el inventario Codex, evalúa la retención y genera los
  informes general, semanal y de posibles bloqueos.
- Usa el Programador de tareas de Windows o `cron`; no incorpora un daemon.
- Mantiene cualquier movimiento de archivos detrás de `--apply-policy`.
- Migra automáticamente las bases existentes para almacenar el evento terminal.

### Verificación

- 6 pruebas aprobadas, incluida una sesión iniciada y otra completada.
- Ejecución real sobre 461 sesiones Codex.
- 1 sesión marcada como potencialmente bloqueada con el umbral de 24 horas.
- 16 candidatas a archivo detectadas en simulación.
- 461 sesiones fuente antes y después de la ejecución: ninguna modificación.
- Los tres informes de mantenimiento se generaron correctamente.

### Límites conocidos

- La señal no analiza semánticamente el texto ni intenta saber si el agente está
  esperando al usuario; requiere revisión humana.
- Solo se aplica a sesiones Codex activas con eventos terminales reconocidos.
- La programación depende deliberadamente del sistema operativo.

## English

### Goal

Detect Codex sessions worth reviewing and support periodic maintenance without
building a resident service.

### Implementation

- Stores each session's latest terminal event: `task_started`, `task_complete`,
  or `turn_aborted`.
- Flags only active sessions whose latest event is `task_started`, with no later
  close event and inactivity beyond `blocked_after_hours`.
- Adds the `blocked` report and the one-shot `maintain` cycle.
- `maintain` refreshes the Codex inventory, evaluates retention, and writes the
  general, weekly, and potentially blocked reports.
- Relies on Windows Task Scheduler or `cron`; no daemon is included.
- Keeps every file move behind `--apply-policy`.
- Automatically migrates existing databases to store terminal events.

### Verification

- 6 tests passed, including one started and one completed session.
- Real run over 461 Codex sessions.
- 1 session flagged as potentially blocked at the 24-hour threshold.
- 16 archive candidates detected in dry-run mode.
- 461 source sessions before and after the run: no modifications.
- All three maintenance reports were generated successfully.

### Known limits

- The signal does not semantically inspect text or infer whether the agent is
  waiting for the user; human review is required.
- It applies only to active Codex sessions with recognized terminal events.
- Scheduling deliberately remains the operating system's responsibility.
