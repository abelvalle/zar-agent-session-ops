# 0.8.0 - Dashboard Angular local / Local Angular dashboard

## Español

### Objetivo

Convertir la API de solo lectura del hito 0.7 en una vista operativa local que
permita revisar el inventario y los posibles bloqueos sin abrir transcripciones.

### Implementación

- Dashboard independiente en `dashboard/` con Angular 22, componentes
  standalone y Angular Material.
- Métricas de sesiones totales, activas, archivadas y potencialmente bloqueadas.
- Filtros locales por agente y estado, con paginación de 25, 50 o 100 filas.
- Tabla adaptable; en móvil conserva las columnas esenciales y permite desplazar
  horizontalmente el detalle restante.
- Estados explícitos de carga, error y ausencia de resultados, con reintento.
- Panel de revisión de bloqueos con el umbral y el último evento terminal.
- Proxy de desarrollo `/api/**` hacia `127.0.0.1:8000`; ambos servidores quedan
  ligados a loopback y no se habilita CORS.
- `/api/health`, `/api/sessions` y `/api/blocked` son las rutas canónicas. Las
  rutas 0.7 sin prefijo continúan funcionando, pero no aparecen en OpenAPI.

La implementación usa `httpResource` para las tres lecturas y señales nativas
para filtros y paginación. No añade una capa de estado global ni una biblioteca
de tablas adicional porque el volumen actual no las necesita.

### Verificación

- 7 pruebas Python aprobadas, incluido el contrato HTTP y OpenAPI.
- 2 pruebas Angular aprobadas: inventario correcto y estado de error.
- `npm audit`: 0 vulnerabilidades.
- Formato Prettier y `git diff --check` sin errores.
- Build de producción: 606,02 kB sin comprimir y 132,66 kB estimados transferidos.
- Prueba real mediante el proxy sobre 461 sesiones: 58 activas, 403 archivadas y
  1 posible bloqueo.
- Filtro interactivo de archivadas: 403 resultados y 25 filas en la primera
  página; todas marcadas como archivadas.
- Revisión visual en 1440 x 900 y 390 x 844: sin desbordamiento del documento ni
  errores o avisos en consola.

### Seguridad y privacidad

- El dashboard y la API escuchan únicamente en `127.0.0.1` durante desarrollo.
- La interfaz solo consume operaciones GET y no puede archivar ni modificar
  sesiones.
- Las respuestas mantienen fuera las rutas de archivos y las transcripciones.
- No existe autenticación; esta versión no debe exponerse en una red ni mediante
  un proxy público.

### Límites conocidos

- La paginación es local: se descarga el inventario de metadatos completo. Se
  añadirá paginación de servidor cuando el volumen real de miles de sesiones lo
  justifique.
- El dashboard muestra el último escaneo guardado; `scan` o `maintain` siguen
  siendo necesarios para actualizarlo.
- No hay endpoints de escritura, autenticación ni empaquetado de despliegue.

Referencias oficiales: [instalación de Angular](https://angular.dev/installation),
[cliente HTTP](https://angular.dev/guide/http/making-requests),
[proxy del servidor de desarrollo](https://angular.dev/tools/cli/serve) y
[pruebas HTTP](https://angular.dev/guide/http/testing).

## English

### Goal

Turn the milestone 0.7 read-only API into a local operational view for reviewing
inventory and potentially blocked sessions without opening transcripts.

### Implementation

- Independent `dashboard/` application with Angular 22, standalone components,
  and Angular Material.
- Metrics for total, active, archived, and potentially blocked sessions.
- Local agent and status filters with 25, 50, or 100-row pagination.
- Responsive table; mobile keeps essential columns visible and allows horizontal
  scrolling for the remaining detail.
- Explicit loading, error, and empty states with retry support.
- Blocked-session review panel with threshold and latest terminal event.
- Development proxy from `/api/**` to `127.0.0.1:8000`; both servers remain
  loopback-bound and CORS is not enabled.
- `/api/health`, `/api/sessions`, and `/api/blocked` are canonical. The
  unprefixed 0.7 routes remain functional but are absent from OpenAPI.

The implementation uses `httpResource` for the three reads and native signals
for filters and pagination. It adds neither global state nor another table
library because the current volume does not need them.

### Verification

- 7 Python tests passed, including the HTTP and OpenAPI contract.
- 2 Angular tests passed: successful inventory and error state.
- `npm audit`: 0 vulnerabilities.
- Prettier formatting and `git diff --check` passed.
- Production build: 606.02 kB uncompressed and 132.66 kB estimated transfer.
- Real proxy-backed run over 461 sessions: 58 active, 403 archived, and 1
  potentially blocked.
- Interactive archived filter: 403 results and 25 first-page rows, all marked
  archived.
- Visual review at 1440 x 900 and 390 x 844: no document overflow, console
  errors, or warnings.

### Security and privacy

- The dashboard and API listen only on `127.0.0.1` during development.
- The interface consumes GET operations only and cannot archive or modify
  sessions.
- Responses continue to exclude source-file paths and transcripts.
- There is no authentication; do not expose this version on a network or behind
  a public proxy.

### Known limits

- Pagination is local: the complete metadata inventory is downloaded. Add
  server pagination when a real workload of thousands of sessions justifies it.
- The dashboard displays the latest stored scan; `scan` or `maintain` is still
  required to refresh it.
- There are no write endpoints, authentication, or deployment packaging.

Official references: [Angular installation](https://angular.dev/installation),
[HTTP client](https://angular.dev/guide/http/making-requests),
[development-server proxy](https://angular.dev/tools/cli/serve), and
[HTTP testing](https://angular.dev/guide/http/testing).
