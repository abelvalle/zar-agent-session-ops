# 0.14.0 - Exportaciones Markdown del dashboard / Dashboard Markdown exports

## Español

### Objetivo

Permitir que una persona descargue la documentación operativa existente desde
la interfaz local sin ejecutar comandos, abrir transcripciones ni duplicar los
generadores de informes.

### API

`GET /api/reports/{report_name}` acepta tres nombres cerrados:

- `sessions`: inventario completo con umbral de antigüedad de siete días.
- `weekly`: sesiones con actividad durante los últimos siete días.
- `blocked`: señales conservadoras calculadas con la política configurada.

Cada respuesta usa `Content-Type: text/markdown; charset=utf-8` y
`Content-Disposition: attachment` con `sessions.md`, `weekly.md` o `blocked.md`.
Un nombre desconocido recibe HTTP 422 y nunca se interpreta como ruta de archivo.

```powershell
Invoke-WebRequest http://127.0.0.1:4200/api/reports/weekly -OutFile weekly.md
```

La API reutiliza `markdown_report`, `weekly_report` y `blocked_report`. No existe
un segundo formato ni una plantilla exclusiva para la web.

### Dashboard

La cabecera incorpora tres enlaces accesibles: **Inventario .md**,
**Semanal .md** y **Bloqueos .md**. Se implementan mediante enlaces HTML nativos
con el atributo `download`; el navegador y `Content-Disposition` gestionan la
descarga sin código de Blob, estado adicional ni una dependencia JavaScript.

Los controles se ajustan en varias filas y se alinean a la izquierda en pantallas
estrechas. El resto del dashboard conserva sus filtros, paginación, consulta
GitHub y actualización en segundo plano.

### Seguridad y privacidad

- Los informes contienen metadatos ya disponibles en la API, no mensajes de la
  conversación ni rutas de los archivos fuente.
- La operación es de solo lectura y no modifica SQLite, la política o las
  sesiones originales.
- Los nombres de informe son valores literales y los nombres de descarga son
  estáticos; no se aceptan rutas aportadas por el usuario.
- El dashboard continúa publicado solo en `127.0.0.1`.

### Verificación

- 14 pruebas Python superadas.
- Los tres informes respondieron HTTP 200, `text/markdown`, nombre de descarga y
  contenido Markdown; un nombre desconocido devolvió HTTP 422.
- El esquema OpenAPI contiene la nueva ruta y las fuentes sintéticas permanecen
  intactas.
- 3 pruebas Angular superadas, incluidas presencia y semántica `download` de los
  tres enlaces.
- Build de producción completado y auditoría npm sin vulnerabilidades.
- Imágenes API y dashboard 0.14.0 construidas; el stack Compose respondió desde
  loopback sobre 478 sesiones reales y descargó los tres informes.

### Límites conocidos

- Los informes se generan bajo demanda y en memoria; la paginación de la tabla no
  limita el contenido descargado.
- El informe semanal descargable es el informe determinista. El digest Ollama de
  0.13 continúa siendo un comando local porque requiere seleccionar un modelo.
- No se añade historial de exportaciones ni almacenamiento de archivos generados.

## English

### Goal

Let a person download existing operational documentation from the local UI
without running commands, opening transcripts, or duplicating report generators.

### API

`GET /api/reports/{report_name}` accepts three closed names:

- `sessions`: complete inventory with a seven-day stale threshold.
- `weekly`: sessions active during the latest seven days.
- `blocked`: conservative signals calculated from the configured policy.

Each response uses `Content-Type: text/markdown; charset=utf-8` and
`Content-Disposition: attachment` with `sessions.md`, `weekly.md`, or
`blocked.md`. An unknown name receives HTTP 422 and is never interpreted as a
filesystem path.

```powershell
Invoke-WebRequest http://127.0.0.1:4200/api/reports/weekly -OutFile weekly.md
```

The API reuses `markdown_report`, `weekly_report`, and `blocked_report`. There is
no second format or web-only template.

### Dashboard

The header adds three accessible links: **Inventory .md**, **Weekly .md**, and
**Blocked .md**. They use native HTML links with the `download` attribute, so the
browser and `Content-Disposition` handle downloads without Blob code, extra
state, or a JavaScript dependency.

Controls wrap across lines and align left on narrow screens. Existing dashboard
filters, pagination, GitHub lookup, and background refresh remain unchanged.

### Security and privacy

- Reports contain metadata already available through the API, not conversation
  messages or source-file paths.
- The operation is read-only and modifies neither SQLite, policy, nor source
  sessions.
- Report names are literal values and download filenames are static; user-supplied
  filesystem paths are not accepted.
- The dashboard remains published only on `127.0.0.1`.

### Verification

- 14 Python tests passed.
- All three reports returned HTTP 200, `text/markdown`, a download filename, and
  Markdown content; an unknown name returned HTTP 422.
- OpenAPI contains the new route and synthetic source files remained unchanged.
- 3 Angular tests passed, including presence and `download` semantics for all
  three links.
- The production build completed and npm audit reported zero vulnerabilities.
- API and dashboard 0.14.0 images built; the Compose stack responded on loopback
  against 478 real sessions and downloaded all three reports.

### Known limits

- Reports are generated on demand and in memory; table pagination does not limit
  downloaded content.
- The downloadable weekly report is deterministic. The 0.13 Ollama digest remains
  a local command because it requires selecting a model.
- No export history or generated-file storage is added.
