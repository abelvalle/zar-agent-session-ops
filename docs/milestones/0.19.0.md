# 0.19.0 - Diagnóstico y consumo de sesiones / Session insight and usage

Fecha / Date: 2026-08-08

## Español

### Objetivo

Completar el tramo de diagnóstico del flujo operativo: pasar de una señal o fila
a una explicación útil sin abandonar el dashboard. El hito también cuantifica el
consumo que Codex registra localmente sin confundir tokens procesados con una
cuota fija de suscripción.

### Resultado

- Los informes semanal, bloqueos e inventario se convierten de Markdown a HTML
  legible dentro de la interfaz. Títulos, listas, código y tablas ya no requieren
  un visor externo.
- La descarga `.md` continúa disponible como acción secundaria.
- `Localizar` filtra, pagina, desplaza el foco y resalta el registro exacto. La
  selección usa identificador, última actividad y tamaño para distinguir copias
  o registros con el mismo identificador.
- La tabla muestra el total de tokens registrado por cada sesión.
- `Consultar` pasa a llamarse `Ver detalle` y abre una ficha con agente, estado,
  origen, tipo, fechas, eventos, tamaño, repositorio y último evento terminal.
- La ficha desglosa entrada no cacheada, entrada en caché, salida, razonamiento,
  total procesado y ventana de contexto.
- Las relaciones GitHub forman parte del detalle, pero un resultado vacío o un
  error de GitHub ya no deja la acción sin valor.
- Un panel agregado muestra sesiones con métricas, tokens históricos deduplicados
  por identificador y la última ventana de uso Codex observada.

### Semántica de consumo

Los JSONL de Codex pueden incluir eventos `token_count`. Se conserva la última
instantánea acumulada de cada archivo:

- `input_tokens`;
- `cached_input_tokens`;
- `output_tokens`;
- `reasoning_output_tokens`;
- `total_tokens`;
- `model_context_window`;
- porcentaje usado, duración y reinicio de la ventana de límite cuando existen.

`cached_input_tokens` forma parte de `input_tokens`, y
`reasoning_output_tokens` forma parte de la salida. La interfaz evita sumarlos de
nuevo en el total. Para el agregado histórico, registros con el mismo identificador
se deduplican conservando el mayor acumulado.

OpenAI documenta que ChatGPT Work y Codex comparten uso, créditos y límites, pero
no publica una equivalencia fija entre una suscripción y un total de tokens. Por
eso la interfaz presenta dos medidas separadas:

1. tokens realmente registrados por las sesiones locales;
2. porcentaje de ventana usado y disponible informado por el evento Codex más
   reciente.

La segunda medida es una instantánea local, no una consulta en tiempo real a la
cuenta. Referencia oficial: [Pricing de ChatGPT Work y Codex](https://learn.chatgpt.com/docs/pricing).

### Migración y privacidad

- SQLite añade columnas numéricas y temporales; no almacena mensajes ni
  transcripciones nuevas.
- `usage_scanned` fuerza una única relectura de sesiones Codex existentes tras
  migrar. Después, los archivos sin cambios vuelven a reutilizar sus metadatos.
- Claude Code, ChatGPT importado y sesiones Codex antiguas muestran `No
  disponible` si la fuente no contiene telemetría compatible.
- El HTML generado por `marked` pasa por el saneamiento de Angular antes de
  insertarse en la página. Las pruebas cubren la eliminación de `script`.
- El endpoint Markdown usa disposición `inline`; el atributo `download` del
  dashboard conserva la descarga explícita.

### Límites conocidos

- La aplicación no puede inferir un total de tokens incluido en la suscripción;
  solo muestra el porcentaje de límite que Codex registró.
- Las métricas no están disponibles si la fuente no contiene `token_count`.
- Este hito mejora diagnóstico y lectura. Archivar, descartar una alerta o generar
  un relevo desde la web siguen pendientes del siguiente tramo operativo.

## English

### Goal

Complete the diagnostic part of the operational flow: move from a signal or row
to useful evidence without leaving the dashboard. The milestone also quantifies
the usage Codex records locally without treating processed tokens as a fixed
subscription allowance.

### Result

- Weekly, blocked, and inventory reports are converted from Markdown into
  readable HTML inside the interface. Headings, lists, code, and tables no longer
  require an external viewer.
- `.md` download remains available as a secondary action.
- `Locate` filters, paginates, moves focus, and highlights the exact record. The
  selection uses identifier, last activity, and size to distinguish copies or
  records that share an identifier.
- The table shows the total tokens recorded for each session.
- `Consult` becomes `View details` and opens a record with agent, status, origin,
  type, timestamps, events, size, repository, and last terminal event.
- The record breaks usage down into uncached input, cached input, output,
  reasoning, total processed tokens, and context window.
- GitHub relationships are part of the record, but an empty result or GitHub
  error no longer makes the action worthless.
- An aggregate panel shows sessions with metrics, historical tokens deduplicated
  by identifier, and the latest observed Codex usage window.

### Usage semantics

Codex JSONL files can contain `token_count` events. The latest cumulative
snapshot from each file is retained:

- `input_tokens`;
- `cached_input_tokens`;
- `output_tokens`;
- `reasoning_output_tokens`;
- `total_tokens`;
- `model_context_window`;
- used percentage, duration, and reset of the limit window when available.

`cached_input_tokens` is part of `input_tokens`, and `reasoning_output_tokens` is
part of output. The interface does not add them again to the total. Historical
aggregation deduplicates records with the same identifier and keeps the largest
cumulative value.

OpenAI documents that ChatGPT Work and Codex share usage, credits, and limits,
but does not publish a fixed conversion between a subscription and a token
total. The interface therefore presents two separate measurements:

1. tokens actually recorded by local sessions;
2. window percentage used and available as reported by the latest Codex event.

The second measurement is a local snapshot, not a live account query. Official
reference: [ChatGPT Work and Codex pricing](https://learn.chatgpt.com/docs/pricing).

### Migration and privacy

- SQLite adds numeric and timestamp columns; it stores no new messages or
  transcripts.
- `usage_scanned` forces one read of existing Codex sessions after migration.
  Unchanged files then return to metadata reuse.
- Claude Code, imported ChatGPT, and older Codex sessions show `Unavailable`
  when their source has no compatible telemetry.
- HTML produced by `marked` passes through Angular sanitization before insertion.
  Tests cover removal of `script` elements.
- The Markdown endpoint uses `inline` disposition; the dashboard's `download`
  attribute preserves explicit downloads.

- This milestone improves diagnosis and reading. Archiving, dismissing an alert,
  or generating a handoff from the web remain part of the next operational step.
