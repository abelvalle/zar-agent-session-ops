# 0.7.0 - API local de solo lectura / Local read-only API

## Español

### Objetivo

Ofrecer una superficie estable para el futuro dashboard sin duplicar la lógica
de inventario ni abrir todavía operaciones remotas de administración.

### Implementación

- `GET /health` devuelve el estado y la versión.
- `GET /sessions` devuelve metadatos y admite filtros `agent` y `status`.
- `GET /blocked` reutiliza la política y la heurística del hito 0.6.
- `serve` inicia Uvicorn ligado de forma fija a `127.0.0.1`.
- FastAPI genera `/docs`, `/redoc` y el esquema OpenAPI.
- Las respuestas omiten `path` y `source_entry`.
- No hay rutas POST, PUT, PATCH o DELETE.

### Verificación

- 7 pruebas aprobadas, incluida una prueba HTTP con `TestClient`.
- Uvicorn iniciado en un puerto efímero de loopback; `/health` respondió `ok`.
- Ejecución real sobre 461 sesiones Codex.
- 3 rutas propias presentes en el esquema OpenAPI.
- 1 posible bloqueo devuelto por la API.
- 461 sesiones fuente antes y después: ninguna modificación.

### Decisión sobre Claude Code y OpenCode

La instalación local de Claude Code solo contenía dos descriptores de proceso en
`.claude/sessions`, sin historial conversacional ni `.claude/projects`.
OpenCode no estaba instalado ni tenía almacenamiento local. Anthropic documenta
la reanudación por identificador y la conservación local temporal, pero no se
encontró un contrato oficial del archivo persistido. Por ello no se creó un
adaptador basado en suposiciones. Referencias: [CLI de Claude Code](https://docs.anthropic.com/en/docs/claude-code/cli-usage)
y [uso y retención de datos](https://docs.anthropic.com/en/docs/claude-code/data-usage).

### Límites conocidos

- No existe autenticación; el servidor es exclusivamente local.
- No hay CORS, dashboard ni endpoints de escritura.
- Para actualizar el inventario hay que ejecutar `scan` o `maintain`.

## English

### Goal

Provide a stable surface for the future dashboard without duplicating inventory
logic or opening remote administration operations yet.

### Implementation

- `GET /health` returns status and version.
- `GET /sessions` returns metadata with optional `agent` and `status` filters.
- `GET /blocked` reuses the milestone 0.6 policy and heuristic.
- `serve` starts Uvicorn with a fixed `127.0.0.1` binding.
- FastAPI generates `/docs`, `/redoc`, and the OpenAPI schema.
- Responses omit `path` and `source_entry`.
- There are no POST, PUT, PATCH, or DELETE routes.

### Verification

- 7 tests passed, including an HTTP test with `TestClient`.
- Uvicorn started on an ephemeral loopback port; `/health` returned `ok`.
- Real run over 461 Codex sessions.
- 3 project routes present in the OpenAPI schema.
- 1 potentially blocked session returned by the API.
- 461 source sessions before and after: no modifications.

### Claude Code and OpenCode decision

The local Claude Code installation contained only two process descriptors under
`.claude/sessions`, with no conversation history or `.claude/projects`.
OpenCode was neither installed nor backed by local storage. Anthropic documents
resume by session ID and temporary local retention, but no official persisted
file contract was found. No assumption-based adapter was added. References:
[Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code/cli-usage) and
[data usage and retention](https://docs.anthropic.com/en/docs/claude-code/data-usage).

### Known limits

- There is no authentication; the server is local-only.
- There is no CORS, dashboard, or write endpoint.
- Run `scan` or `maintain` to refresh the inventory.
