# 0.13.0 - Informe operativo semanal / Weekly operational digest

## Español

### Objetivo

Convertir la actividad reciente de varias sesiones Codex y ChatGPT en un único
informe útil para seguimiento semanal, sin copiar transcripciones ni crear un
servicio nuevo.

### Implementación

- `weekly-digest --model MODEL` selecciona sesiones con actividad durante los
  últimos siete días y genera `weekly-digest.md` mediante Ollama.
- Se procesan como máximo las 12 sesiones más recientes y un total de 24.000
  caracteres. Ambos límites pueden reducirse con `--max-sessions` y
  `--max-chars`.
- Cada fragmento identifica sesión, agente, repositorio y última actividad antes
  de incluir los mensajes recientes de usuario y asistente.
- Una sola llamada a Ollama produce cinco apartados: resumen semanal, decisiones
  técnicas, tareas pendientes, riesgos y commits o Pull Requests.
- Las referencias GitHub deben proceder de URLs completas presentes en las
  conversaciones; el prompt prohíbe inferir relaciones por nombre o fecha.
- `extract_session_transcript` centraliza la selección del extractor Codex o
  ChatGPT y elimina la duplicación previa en `summarize` y `handoff`.

```powershell
python -m zar_agent_session_ops weekly-digest --model qwen3:8b
```

### Mantenimiento programado

`maintain` conserva su ejecución sin modelos por defecto. Cuando se pasa
`--model`, añade `weekly-digest.md` al mismo directorio que `sessions.md`,
`weekly.md` y `blocked.md`.

```powershell
python -m zar_agent_session_ops maintain --model qwen3:8b
```

El ciclo realiza una sola generación. Un error de Ollama hace fallar la ejecución
y se comunica al planificador mediante código de salida distinto de cero; las
sesiones fuente permanecen intactas.

### Seguridad y privacidad

- Solo se leen mensajes de usuario y asistente desde las fuentes ya soportadas.
- El prompt está limitado antes de enviarse exclusivamente a
  `127.0.0.1:11434`.
- La aplicación no concatena la transcripción al informe ni la persiste en
  SQLite.
- No se consulta GitHub durante la generación; las URLs explícitas se conservan
  como evidencia y el comando `github` sigue siendo la vía para resolver estado
  y título.

### Verificación

- 14 pruebas Python superadas.
- La prueba del digest excluye sesiones fuera de siete días, selecciona solo la
  más reciente cuando el límite es uno, respeta el presupuesto de caracteres y
  conserva una URL de Pull Request explícita.
- El adaptador común se verificó también sobre una conversación ChatGPT sintética.
- `maintain --model` generó el archivo adicional sin alterar el flujo sin modelo.
- 3 pruebas Angular superadas, build de producción completado y auditoría npm sin
  vulnerabilidades.
- Imágenes API y dashboard 0.13.0 construidas; stack Compose validado en loopback
  sobre 477 sesiones Codex reales.
- Ollama está instalado pero no contiene un modelo local; la petición se validó
  contra una respuesta HTTP simulada y no se descargó un modelo sin autorización.

### Límites conocidos

- La calidad semántica depende del modelo Ollama elegido.
- Si existen más de 12 sesiones activas durante la semana, se priorizan las más
  recientes.
- El presupuesto se reparte entre las sesiones seleccionadas; no pretende ser un
  archivo exhaustivo de la semana.
- El dashboard no inicia ni muestra el digest en este hito.

## English

### Goal

Turn recent activity across Codex and ChatGPT sessions into one useful weekly
tracking report without copying transcripts or adding a new service.

### Implementation

- `weekly-digest --model MODEL` selects sessions active during the latest seven
  days and generates `weekly-digest.md` through Ollama.
- It processes at most the 12 most recent sessions and 24,000 total characters.
  `--max-sessions` and `--max-chars` can lower both limits.
- Each excerpt identifies its session, agent, repository, and latest activity
  before recent user and assistant messages.
- One Ollama request produces five sections: weekly summary, technical decisions,
  pending tasks, risks, and commits or Pull Requests.
- GitHub references must come from complete URLs present in conversations; the
  prompt forbids inferring relationships by name or date.
- `extract_session_transcript` centralizes Codex or ChatGPT extractor selection
  and removes the previous duplication in `summarize` and `handoff`.

```powershell
python -m zar_agent_session_ops weekly-digest --model qwen3:8b
```

### Scheduled maintenance

`maintain` preserves its model-free default behavior. When `--model` is passed,
it adds `weekly-digest.md` beside `sessions.md`, `weekly.md`, and `blocked.md`.

```powershell
python -m zar_agent_session_ops maintain --model qwen3:8b
```

The cycle performs one generation. An Ollama error fails the run and reports a
non-zero exit code to the scheduler while source sessions remain untouched.

### Security and privacy

- Only user and assistant messages are read from already supported sources.
- The prompt is bounded before being sent exclusively to `127.0.0.1:11434`.
- The application neither appends the transcript to the report nor persists it
  in SQLite.
- Generation does not query GitHub. Explicit URLs remain evidence, while the
  `github` command remains the path for resolving title and state.

### Verification

- 14 Python tests passed.
- The digest test excludes sessions outside seven days, selects only the newest
  when the limit is one, respects the character budget, and preserves an
  explicit Pull Request URL.
- The shared adapter was also verified against a synthetic ChatGPT conversation.
- `maintain --model` produced the additional file without changing the
  model-free flow.
- 3 Angular tests passed, the production build completed, and npm audit reported
  zero vulnerabilities.
- API and dashboard 0.13.0 images built; the Compose stack was validated on
  loopback against 477 real Codex sessions.
- Ollama is installed but contains no local model. The request was verified
  against a simulated HTTP response, and no model was downloaded without
  authorization.

### Known limits

- Semantic quality depends on the selected Ollama model.
- When more than 12 sessions are active during the week, the newest take priority.
- The character budget is divided across selected sessions; this is not intended
  to be an exhaustive weekly archive.
- The dashboard neither starts nor displays the digest in this milestone.
