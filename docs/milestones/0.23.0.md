# 0.23.0 - Búsqueda operativa de sesiones / Operational session search

Fecha / Date: 2026-08-09

## Español

### Objetivo

Reducir el inventario de cientos de sesiones a la ficha relevante sin recorrer
páginas manualmente ni perder los filtros operativos existentes.

### Resultado

- `Buscar sesiones` filtra en memoria por título, identificador de sesión,
  `record_key`, repositorio, agente, nombre visible del agente, origen y tipo de
  hilo.
- La consulta ignora mayúsculas y minúsculas, se combina con agente y estado y
  devuelve la paginación a la primera página con cada cambio.
- El encabezado distingue el total filtrado del inventario completo.
- `Limpiar búsqueda` restaura el inventario sin alterar los filtros de agente y
  estado.
- Las acciones `Localizar` limpian una consulta incompatible antes de calcular
  la página y enfocar la fila exacta.
- El estado vacío conserva la consulta para explicar por qué no hay resultados.

### Contrato y privacidad

- La búsqueda se ejecuta íntegramente en el navegador sobre los metadatos que ya
  entrega `GET /api/sessions`; no añade llamadas, persistencia ni índices.
- No lee transcripciones, no genera resúmenes y no modifica sesiones ni
  decisiones de ciclo de vida.

### Verificación

- 21 pruebas Python superadas sin regresiones.
- 7 pruebas Angular superadas, incluida búsqueda sin distinción de mayúsculas,
  contador filtrado y limpieza.
- Build Angular de producción completado dentro del presupuesto.
- `npm audit --audit-level=moderate`: 0 vulnerabilidades.
- Detector Impeccable sobre HTML, SCSS y TypeScript: 0 hallazgos.
- Stack Docker 0.23 construido con API saludable y dashboard disponible en
  `http://127.0.0.1:4200`.
- Navegador real validado buscando una sesión existente, abriendo su ficha y
  limpiando la consulta; ninguna sesión fue modificada.

### Decisión de alcance

El historial Claude Code y el adaptador OpenCode siguen aplazados: esta máquina
no contiene transcripciones Claude Code JSONL ni datos OpenCode reales que
permitan implementar y verificar sus formatos sin inventar fixtures.

## English

### Goal

Reduce an inventory of hundreds of sessions to the relevant record without
manually paging or losing the existing operational filters.

### Result

- `Search sessions` filters in memory by title, session identifier, `record_key`,
  repository, agent, visible agent name, origin, and thread type.
- The query is case-insensitive, combines with agent and status, and returns
  pagination to the first page on every change.
- The heading distinguishes the filtered total from the complete inventory.
- `Clear search` restores the inventory without changing agent or status
  filters.
- `Locate` actions clear an incompatible query before calculating the page and
  focusing the exact row.
- The empty state retains the query to explain why no result exists.

### Contract and privacy

- Search runs entirely in the browser over metadata already returned by
  `GET /api/sessions`; it adds no calls, persistence, or indexes.
- It reads no transcripts, generates no summaries, and changes neither sessions
  nor lifecycle decisions.

### Verification

- 21 Python tests passed without regressions.
- 7 Angular tests passed, including case-insensitive search, filtered count, and
  clearing.
- Production Angular build completed within budget.
- `npm audit --audit-level=moderate`: 0 vulnerabilities.
- Impeccable detector over HTML, SCSS, and TypeScript: 0 findings.
- Docker 0.23 stack built with a healthy API and dashboard available at
  `http://127.0.0.1:4200`.
- Real-browser validation searched an existing session, opened its record, and
  cleared the query; no session was modified.

### Scope decision

Claude Code history and the OpenCode adapter remain deferred: this machine has
neither Claude Code JSONL transcripts nor real OpenCode data that would allow
their formats to be implemented and verified without invented fixtures.
