# 0.18.0 - Informes Markdown integrados / Inline Markdown reports

## Español

### Objetivo

Permitir que los informes generados por la aplicación se consulten dentro del
dashboard en lugar de obligar a descargar un archivo para conocer su contenido.
La descarga se conserva como salida opcional, no como navegación principal.

### Lector integrado

La sección **Informes** aparece después de la cola de atención y antes del
inventario completo. Ofrece tres vistas:

- **Semanal**, seleccionada por defecto;
- **Bloqueos**;
- **Inventario**.

El cambio de vista actualiza el recurso de texto desde
`GET /api/reports/{report_name}`. El contenido se muestra en una región de lectura
con altura limitada, desplazamiento propio y navegación por teclado. Las tablas
Markdown anchas se desplazan dentro del lector y no ensanchan la página.

La barra del lector identifica el informe seleccionado y ofrece **Descargar
.md** como acción secundaria. La URL y el nombre de archivo se actualizan con la
selección actual.

### Estados y actualización

- Mientras llega el texto se muestra progreso con etiqueta accesible.
- Un fallo del informe no bloquea inventario, atención ni el resto de la API.
- El error explica la recuperación y permite **Reintentar informe**.
- Al finalizar un refresco de sesiones, el informe visible también se recarga
  para reflejar los nuevos metadatos.

### Seguridad y alcance

- Se reutilizan los endpoints y generadores existentes; no hay una segunda
  implementación del contenido.
- El texto se interpola como contenido, no como HTML, por lo que títulos o
  repositorios no pueden inyectar marcado ejecutable.
- No se cargan librerías de Markdown ni recursos externos.
- La lectura y descarga no modifican SQLite ni los archivos de sesión.

### Verificación

- 17 pruebas Python superadas sin cambios de contrato en la API.
- 5 pruebas Angular con informe inicial, cambio de selección, descarga asociada,
  error, reintento y recarga tras actualizar sesiones.
- Build Angular de producción y detector Impeccable sin hallazgos.
- Auditoría npm sin vulnerabilidades.
- Imágenes API y dashboard 0.18.0 construidas; stack Compose saludable sobre el
  inventario local real.
- Los tres informes reales se consultaron desde el dashboard y la consola del
  navegador permaneció sin errores.
- Vista de escritorio y móvil comprobadas sin desbordamiento horizontal de la
  página.

### Límites conocidos

- El lector conserva la sintaxis Markdown como texto monoespaciado; no interpreta
  HTML ni convierte tablas en componentes interactivos.
- El inventario completo puede requerir desplazamiento vertical y horizontal
  dentro del lector.
- No existe historial de informes: el contenido se genera en cada petición.

## English

### Goal

Allow application reports to be read inside the dashboard instead of requiring
a file download before their content can be inspected. Download remains an
optional output, not the primary navigation.

### Inline reader

The **Reports** section appears after the attention queue and before the full
inventory. It offers three views:

- **Weekly**, selected by default;
- **Blocked**;
- **Inventory**.

Changing the view updates the text resource from
`GET /api/reports/{report_name}`. Content is shown in a bounded reading region
with its own scrolling and keyboard navigation. Wide Markdown tables scroll
inside the reader instead of widening the page.

The reader toolbar identifies the selected report and provides **Download .md**
as a secondary action. Its URL and file name follow the current selection.

### States and refresh

- An accessible progress indicator is shown while text is loading.
- A report failure does not block inventory, attention, or the rest of the API.
- The error explains recovery and provides **Retry report**.
- When a session refresh completes, the visible report reloads to reflect the
  latest metadata.

### Security and scope

- Existing endpoints and generators are reused; there is no second report
  implementation.
- Text is interpolated as content rather than HTML, so titles and repositories
  cannot inject executable markup.
- No Markdown libraries or external resources are loaded.
- Reading and downloading modify neither SQLite nor session files.

### Verification

- 17 Python tests passed with no API contract change.
- 5 Angular tests cover initial report, selection changes, associated download,
  error, retry, and reload after session refresh.
- Production Angular build and Impeccable detector with no findings.
- npm audit with zero vulnerabilities.
- API and dashboard 0.18.0 images built; Compose stack healthy against the real
  local inventory.
- All three real reports inspected from the dashboard with no browser console
  errors.
- Desktop and mobile layouts checked without page-level horizontal overflow.

### Known limits

- The reader preserves Markdown syntax as monospaced text; it does not interpret
  HTML or turn tables into interactive components.
- The full inventory may require vertical and horizontal scrolling inside the
  reader.
- There is no report history; content is generated for each request.
