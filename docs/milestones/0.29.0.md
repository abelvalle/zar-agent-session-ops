# 0.29.0 - Resúmenes locales visibles / Visible local summaries

## Español

### Objetivo

Convertir la integración Ollama existente en una capacidad comprensible desde
la web: conocer su estado real, usar solo modelos ya instalados y leer el
resultado sin descargar un archivo externo.

### Entregado

- `GET /api/ollama` distingue `ready`, `no_models` y `unavailable` y devuelve
  solo los nombres anunciados por el Ollama local.
- `POST /api/sessions/{record_key}/summary` verifica que el modelo solicitado
  esté instalado, extrae un transcript acotado y devuelve Markdown no
  persistente.
- El dashboard explica el estado de Ollama junto a las fuentes y deshabilita de
  forma explícita la generación cuando faltan servicio o modelos.
- La ficha permite elegir un modelo instalado, generar el resumen bajo demanda
  y leer el Markdown renderizado en la propia interfaz.
- Compose conecta la API con el Ollama de la máquina anfitriona mediante
  `host.docker.internal:11434`; la validación rechaza hosts, puertos,
  credenciales y rutas remotas.
- La aplicación no ejecuta `ollama pull`, no descarga modelos y no guarda el
  resumen ni el transcript en SQLite.

### Criterios verificados

- 27 pruebas Python, incluida disponibilidad vacía, servicio no disponible,
  rechazo sin modelo y generación con un modelo instalado simulado.
- 7 pruebas Angular, incluido el estado sin modelos y el resumen Markdown
  visible y saneado dentro de la ficha.
- Build Angular de producción sin advertencias y auditoría npm sin
  vulnerabilidades moderadas o superiores.
- Formato Prettier, comprobación de espacios Git y detector de interfaz.
- Stack Docker 0.29 saludable y estado real de Ollama comprobado desde la API y
  desde el navegador, sin instalar ningún modelo.

## English

### Goal

Turn the existing Ollama integration into an understandable web capability:
report its actual state, use installed models only, and read the result without
downloading an external file.

### Delivered

- `GET /api/ollama` distinguishes `ready`, `no_models`, and `unavailable` and
  returns only names advertised by the local Ollama instance.
- `POST /api/sessions/{record_key}/summary` verifies that the selected model is
  installed, extracts a bounded transcript, and returns non-persistent
  Markdown.
- The dashboard explains Ollama status beside session sources and explicitly
  disables generation when the service or models are missing.
- A record can select an installed model, request a summary, and read rendered
  Markdown in the interface.
- Compose reaches the host's Ollama through `host.docker.internal:11434`; input
  validation rejects remote hosts, ports, credentials, and paths.
- The application never runs `ollama pull`, downloads models, or stores the
  summary or transcript in SQLite.

### Verified criteria

- 27 Python tests, including empty availability, unavailable service, rejection
  without a model, and generation with a simulated installed model.
- 7 Angular tests, including the no-model state and sanitized inline Markdown
  summary.
- Warning-free production Angular build and npm audit with no moderate-or-higher
  vulnerabilities.
- Prettier formatting, Git whitespace check, and UI detector.
- Healthy Docker 0.29 stack and actual Ollama state checked through the API and
  browser without installing any model.
