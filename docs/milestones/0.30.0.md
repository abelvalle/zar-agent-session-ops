# 0.30.0 - Historial de informes operativos / Operational report history

## Español

### Objetivo

Completar el recorrido del informe semanal: generarlo con el Ollama local,
leerlo dentro del dashboard y recuperar ejecuciones anteriores sin depender de
una descarga Markdown.

### Entrega

- `POST /api/digests/weekly` acepta únicamente un modelo anunciado por el
  Ollama local, reutiliza la selección acotada del informe semanal y guarda el
  resultado.
- `GET /api/digests/weekly` devuelve las ejecuciones más recientes primero.
- SQLite conserva fecha, modelo y Markdown generado. No guarda la transcripción
  ni las rutas fuente.
- El dashboard diferencia Ollama disponible, sin modelos y no disponible. Nunca
  instala ni descarga un modelo.
- La interfaz permite generar, seleccionar y leer informes anteriores sin salir
  de la aplicación.

### Límites deliberados

- La generación es manual. El planificador automático sigue siendo un hito
  separado.
- Sin un modelo local instalado, la interfaz explica el bloqueo y no simula un
  resultado.
- El historial pertenece a la base local de la aplicación y no se sincroniza
  con servicios externos.

### Verificación

- 28 pruebas Python para persistencia, validación de modelo y contrato API.
- 7 pruebas Angular para estados de Ollama, generación, historial y regresiones
  del dashboard.
- Build Angular de producción y auditoría npm.
- Detector de calidad visual sin hallazgos.
- Stack Docker 0.30 comprobado en loopback con Ollama sin modelos, sin realizar
  descargas automáticas.

## English

### Goal

Complete the weekly-report journey: generate it through local Ollama, read it
inside the dashboard, and recover previous runs without relying on a Markdown
download.

### Delivery

- `POST /api/digests/weekly` accepts only a model advertised by local Ollama,
  reuses the bounded weekly selection, and stores the result.
- `GET /api/digests/weekly` returns the newest runs first.
- SQLite stores the date, model, and generated Markdown. It stores neither the
  transcript nor source paths.
- The dashboard distinguishes ready Ollama, no models, and unavailable states.
  It never installs or downloads a model.
- The interface can generate, select, and read previous reports without leaving
  the application.

### Deliberate limits

- Generation is manual. Automatic scheduling remains a separate milestone.
- Without an installed local model, the interface explains the blocker and
  does not simulate a result.
- History belongs to the local application database and is not synchronized
  with external services.

### Verification

- 28 Python tests for persistence, model validation, and the API contract.
- 7 Angular tests for Ollama states, generation, history, and dashboard
  regressions.
- Production Angular build and npm audit.
- UI quality detector with no findings.
- Docker stack 0.30 checked on loopback with Ollama reporting no models and no
  automatic downloads.
