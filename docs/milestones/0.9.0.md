# 0.9.0 - Relaciones con GitHub / GitHub relationships

## Español

### Objetivo

Relacionar una sesión con Issues, Pull Requests y commits verificables sin
atribuir trabajo por heurísticas ni enviar la conversación completa a un
servicio remoto.

### Implementación

- Extracción de URLs completas `github.com/{owner}/{repo}/issues/{number}`,
  `pull/{number}` y `commit/{sha}` desde mensajes de usuario y asistente.
- Lectura acotada a los últimos 200.000 caracteres y a 20 referencias únicas.
- Resolución de título y estado mediante endpoints GET de la API REST de GitHub.
- API fijada a la versión `2026-03-10`, con `Accept` y `User-Agent` explícitos.
- Acceso público sin token y autenticación Bearer opcional mediante
  `GITHUB_TOKEN`; el valor no se persiste ni aparece en respuestas o registros.
- Comando `github SESSION_ID` con salida JSON.
- Endpoint `GET /api/sessions/{session_id}/github`, con 404 para sesiones
  inexistentes y 422 para fuentes locales no legibles.
- Botón bajo demanda por fila y panel responsive en el dashboard. No se realizan
  consultas GitHub al cargar las 461 sesiones.
- Compatibilidad con sesiones Codex e importaciones ChatGPT mediante sus lectores
  de transcripción existentes.

### Decisiones de seguridad y precisión

- Las peticiones siempre apuntan al host fijo `api.github.com`; los segmentos de
  ruta extraídos se codifican antes de construir la URL.
- Solo se envían propietario, repositorio y número o SHA ya presentes en un
  enlace explícito. La transcripción no sale del equipo.
- No se interpretan `#123`, SHAs sin URL, nombres de ramas ni coincidencias por
  hora o repositorio porque producirían relaciones ambiguas.
- La operación es exclusivamente de lectura. No existen rutas para crear,
  comentar, cerrar o fusionar recursos.
- Un error en una referencia queda anotado en esa referencia y no oculta las
  demás relaciones válidas.

### Verificación

- 11 pruebas Python aprobadas: extracción, deduplicación, Issues, Pull Requests,
  commits, autenticación, versión de API, preservación de fuentes y contrato
  HTTP/OpenAPI.
- 2 pruebas Angular aprobadas: inventario con consulta GitHub y estado global de
  error.
- Consulta pública real del commit `fac3330`: título resuelto correctamente.
- Ejecución real sobre esta sesión y 461 registros: 8 commits relacionados,
  todos disponibles.
- Flujo dashboard real: una única petición bajo demanda, 8 enlaces y 0 errores.
- Revisión visual a 1440 x 900 y 390 x 844: sin desbordamiento horizontal del
  documento; lista móvil en una columna.
- Consola del navegador sin errores ni avisos.
- Build de producción: 611,06 kB sin comprimir y 133,67 kB estimados transferidos.

### Límites conocidos

- Solo se inspecciona la cola de 200.000 caracteres; se añadirá lectura completa
  en streaming si aparecen pérdidas reales.
- No hay caché: volver a consultar una sesión repite las peticiones y consume el
  límite de GitHub.
- GitHub Enterprise Server y otros hosts no están soportados en esta versión.
- La integración no descubre automáticamente recursos que nunca se enlazaron en
  la conversación.

## English

### Goal

Relate a session to verifiable Issues, Pull Requests, and commits without
heuristic work attribution or sending the complete conversation to a remote
service.

### Implementation

- Extracts complete `github.com/{owner}/{repo}/issues/{number}`,
  `pull/{number}`, and `commit/{sha}` URLs from user and assistant messages.
- Reads at most the latest 200,000 characters and 20 unique references.
- Resolves title and state through GET endpoints in GitHub's REST API.
- Pins API version `2026-03-10` with explicit `Accept` and `User-Agent` headers.
- Supports public access without a token and optional Bearer authentication via
  `GITHUB_TOKEN`; the value is neither persisted nor returned or logged.
- Adds a JSON-producing `github SESSION_ID` command.
- Adds `GET /api/sessions/{session_id}/github`, returning 404 for unknown
  sessions and 422 for unreadable local sources.
- Adds an on-demand row action and responsive dashboard panel. Loading the 461
  sessions does not trigger any GitHub request.
- Supports Codex sessions and ChatGPT imports through their existing transcript
  readers.

### Security and accuracy decisions

- Requests always target the fixed `api.github.com` host; extracted path segments
  are encoded before URL construction.
- Only the owner, repository, and number or SHA already present in an explicit
  link are sent. The transcript never leaves the machine.
- `#123`, unlinked SHAs, branch names, and time or repository coincidences are
  ignored because they would create ambiguous relationships.
- The integration is read-only. No route can create, comment on, close, or merge
  a resource.
- A per-reference failure remains attached to that item and does not hide other
  valid relationships.

### Verification

- 11 Python tests passed: extraction, deduplication, Issues, Pull Requests,
  commits, authentication, API version, source preservation, and HTTP/OpenAPI
  contract.
- 2 Angular tests passed: inventory with GitHub lookup and global error state.
- Live public lookup of commit `fac3330` resolved the correct title.
- Real run over this session and 461 records: 8 related commits, all available.
- Real dashboard flow: one on-demand request, 8 links, and 0 errors.
- Visual review at 1440 x 900 and 390 x 844: no document-level horizontal
  overflow; the mobile list uses one column.
- Browser console contained no errors or warnings.
- Production build: 611.06 kB uncompressed and 133.67 kB estimated transfer.

### Known limits

- Only the latest 200,000 characters are inspected; add full streaming when real
  misses appear.
- There is no cache; querying a session again repeats requests and consumes the
  GitHub rate limit.
- GitHub Enterprise Server and other hosts are unsupported in this version.
- The integration cannot discover resources that were never linked in the
  conversation.
