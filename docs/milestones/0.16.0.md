# 0.16.0 - Vista previa de retención / Retention preview

## Español

### Objetivo

Hacer visible la política de archivado antes de ejecutar una operación que mueve
archivos. El hito reutiliza la selección ya probada por la CLI y conserva la web
como una superficie de inspección: no añade botones de aplicar, confirmar o
archivar.

### Contrato API

`GET /api/retention` devuelve:

- `count`: número de sesiones candidatas;
- `archive_after_days`: umbral configurado;
- `sessions`: metadatos normalizados mediante el mismo contrato que el
  inventario.

La respuesta omite `archive_dir` y las rutas de archivos fuente. Una candidata
debe tener estado `active` y una antigüedad igual o superior al umbral. Por ese
contrato quedan fuera:

- sesiones Codex ya archivadas;
- conversaciones ChatGPT con estado `imported`;
- registros Claude Code con estado `registered`.

La API reutiliza `load_policy`, `load_sessions`, `policy_candidates` y
`_session_data`; no mantiene una segunda implementación de la política.

### Dashboard

La sección **Vista previa de retención** muestra el umbral, el recuento y, cuando
existen, el nombre y última actividad de cada candidata. Si ninguna sesión
cumple la política, muestra un estado vacío explícito.

La vista participa en los estados globales de carga, error y recarga. Al terminar
un refresco del inventario, se vuelve a consultar junto con sesiones y bloqueos.

### Seguridad

- El endpoint es `GET` y no escribe en SQLite ni en las fuentes.
- No se devuelve el directorio de destino configurado.
- No existe una ruta web para aplicar la política.
- `--apply` y `--apply-policy` siguen siendo los únicos mecanismos explícitos
  que permiten mover archivos desde la CLI.
- La API y el dashboard continúan ligados exclusivamente a loopback.

### Verificación

- 16 pruebas Python superadas, incluida la exclusión de un registro Claude y la
  ausencia de `archive_dir` en la respuesta.
- El esquema OpenAPI incluye `GET /api/retention`.
- La pila real devolvió 3 candidatas Codex activas con umbral de 30 días y sin
  `archive_dir`, sobre un inventario de 480 sesiones.
- 3 pruebas Angular superadas con candidata, estado vacío, error y recarga.
- Build de producción completado y auditoría npm sin vulnerabilidades.
- Imágenes API y dashboard 0.16.0 construidas y stack Compose validado sobre el
  inventario real sin modificar archivos fuente.
- Revisión visual del panel y consola del navegador sin errores.

### Límites conocidos

- La vista previa usa días completos, igual que la CLI existente.
- No muestra ni permite cambiar la configuración TOML.
- No aplica ni programa el archivado desde la web.
- La autenticación y el acceso fuera de loopback siguen fuera de alcance.

## English

### Goal

Make archive policy visible before running an operation that moves files. This
milestone reuses the selection already tested by the CLI and keeps the web UI as
an inspection surface: it adds no apply, confirm, or archive buttons.

### API contract

`GET /api/retention` returns:

- `count`: number of candidate sessions;
- `archive_after_days`: configured threshold;
- `sessions`: metadata normalized through the inventory contract.

The response omits `archive_dir` and source-file paths. A candidate must have
`active` status and age equal to or greater than the threshold. This contract
excludes:

- already archived Codex sessions;
- ChatGPT conversations with `imported` status;
- Claude Code records with `registered` status.

The API reuses `load_policy`, `load_sessions`, `policy_candidates`, and
`_session_data`; it does not maintain a second policy implementation.

### Dashboard

The **Retention preview** section shows the threshold, count, and, when present,
each candidate's name and latest activity. When no session matches policy, it
shows an explicit empty state.

The view participates in global loading, error, and reload states. After an
inventory refresh completes, it reloads together with sessions and blocked
signals.

### Security

- The endpoint is `GET` and writes neither SQLite nor source files.
- The configured destination directory is not returned.
- No web route applies policy.
- `--apply` and `--apply-policy` remain the only explicit mechanisms that allow
  the CLI to move files.
- API and dashboard remain loopback-only.

### Verification

- 16 Python tests passed, including exclusion of a Claude record and absence of
  `archive_dir` from the response.
- OpenAPI includes `GET /api/retention`.
- The real stack returned 3 active Codex candidates with a 30-day threshold and
  no `archive_dir`, against an inventory of 480 sessions.
- 3 Angular tests passed with candidate, empty, error, and reload states.
- The production build completed and npm audit reported zero vulnerabilities.
- API and dashboard 0.16.0 images built; Compose was validated against the real
  inventory without modifying source files.
- Visual panel review and browser console completed without errors.

### Known limits

- Preview uses whole days, matching the existing CLI.
- It neither displays nor edits TOML configuration.
- It does not apply or schedule archive from the web.
- Authentication and access beyond loopback remain out of scope.
