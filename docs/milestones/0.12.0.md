# 0.12.0 - Relevo de contexto mínimo / Minimal-context handoff

## Español

### Objetivo

Continuar el trabajo de una sesión Codex o ChatGPT en una conversación nueva
sin trasladar la transcripción completa ni perder las decisiones operativas.

### Implementación

- `handoff SESSION_ID --model MODEL` reutiliza la sesión ya indexada y los
  extractores Codex o ChatGPT existentes.
- Ollama recibe como máximo los últimos 24.000 caracteres de mensajes de usuario
  y asistente; el límite se puede reducir con `--max-chars`.
- El Markdown conserva metadatos mínimos y seis apartados: objetivo, trabajo
  completado, decisiones técnicas, tareas pendientes, riesgos y primera acción.
- El modelo debe usar el idioma dominante, limitarse a evidencia explícita y
  declarar cuando no identifica información para un apartado.
- `--output` permite elegir el destino; el valor predeterminado es
  `session-handoff.md`.

```powershell
python -m zar_agent_session_ops handoff SESSION_ID --model qwen3:8b --output session-handoff.md
```

### Codex y ChatGPT

En Codex se inicia una tarea separada con `/new` y se adjunta o pega el relevo.
En ChatGPT se abre un chat nuevo y se adjunta el mismo Markdown. El proyecto no
automatiza la creación: así evita depender de una superficie concreta y mantiene
el archivo portable entre CLI, aplicación, IDE y web.

El manual oficial indica que `codex fork` crea un chat nuevo conservando la
transcripción anterior. Por ello no se utiliza para este flujo, cuyo propósito
es reducir el contexto. También recomienda mantener orientación duradera en
`AGENTS.md` o documentación versionada para que esté disponible en tareas
futuras.

### Seguridad y fallos

- La transcripción se lee de su fuente y solo se envía a Ollama en
  `127.0.0.1:11434`.
- La aplicación no concatena la transcripción al resultado ni modifica la
  sesión fuente o la base SQLite.
- Los errores al leer la sesión o generar con Ollama conservan una salida
  anterior porque el archivo solo se escribe después de generar el relevo.

### Verificación

- 13 pruebas Python superadas, incluidas generación Codex sin copiar la
  transcripción y selección del extractor ChatGPT desde el comando.
- 3 pruebas Angular superadas y build de producción completado.
- Auditoría npm sin vulnerabilidades.
- Imágenes API y dashboard 0.12.0 construidas y stack Compose validado en
  loopback.

### Límites conocidos

- Ollama debe estar instalado, ejecutándose y disponer del modelo indicado.
- La calidad del relevo depende del modelo local y de la evidencia presente en
  la ventana final de la transcripción.
- El comando no crea ni envía una tarea automáticamente; el usuario decide en
  qué superficie consumir el Markdown.
- El dashboard no expone transcripciones ni generación de relevos en este hito.

Referencias oficiales: [proyectos y chats de Codex](https://learn.chatgpt.com/docs/projects-and-chats)
y [referencia de comandos de Codex](https://learn.chatgpt.com/docs/developer-commands?surface=cli#cli-codex-fork).

## English

### Goal

Continue work from a Codex or ChatGPT session in a new conversation without
carrying the complete transcript or losing operational decisions.

### Implementation

- `handoff SESSION_ID --model MODEL` reuses the indexed session and the existing
  Codex or ChatGPT extractors.
- Ollama receives at most the latest 24,000 characters of user and assistant
  messages; `--max-chars` can lower that limit.
- Markdown retains minimal metadata and six sections: goal, completed work,
  technical decisions, pending tasks, risks, and first next action.
- The model must use the transcript's dominant language, rely only on explicit
  evidence, and state when no information is identified for a section.
- `--output` selects the destination and defaults to `session-handoff.md`.

```powershell
python -m zar_agent_session_ops handoff SESSION_ID --model qwen3:8b --output session-handoff.md
```

### Codex and ChatGPT

In Codex, start a separate task with `/new`, then attach or paste the handoff.
In ChatGPT, open a new chat and attach the same Markdown. The project does not
automate creation, avoiding a dependency on one product surface and keeping the
file portable across CLI, app, IDE, and web.

The official manual states that `codex fork` creates a new chat while preserving
the previous transcript. It is therefore unsuitable for a flow intended to
reduce context. The manual also recommends keeping durable guidance in
`AGENTS.md` or checked-in documentation for future tasks.

### Security and failures

- The transcript is read from its source and sent only to Ollama at
  `127.0.0.1:11434`.
- The application does not append the transcript to the result and modifies
  neither the source session nor SQLite.
- Session-read or Ollama generation failures preserve an existing output because
  the file is written only after generation completes.

### Verification

- 13 Python tests passed, including Codex generation without transcript copying
  and ChatGPT extractor selection from the command.
- 3 Angular tests passed and the production build completed.
- npm audit reported zero vulnerabilities.
- API and dashboard 0.12.0 images built, and the Compose stack was validated on
  loopback.

### Known limits

- Ollama must be installed, running, and have the selected model available.
- Handoff quality depends on the local model and evidence in the final transcript
  window.
- The command does not create or submit a task automatically; the user chooses
  which surface consumes the Markdown.
- The dashboard exposes neither transcripts nor handoff generation in this
  milestone.
