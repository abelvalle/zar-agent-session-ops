# 0.15.0 - Registro de sesiones Claude Code / Claude Code session registry

## Español

### Objetivo

Incorporar la primera fuente real de Claude Code al inventario común sin afirmar
capacidades que sus archivos disponibles no proporcionan. El hito usa registros
locales observados en `CLAUDE_HOME/sessions/*.json`; no inventa un formato de
transcripción ni depende de procesos internos de Claude.

### Contrato de la fuente

Cada JSON válido debe incluir `sessionId`. El adaptador normaliza además, cuando
existen:

- `cwd` como repositorio o directorio de trabajo;
- `startedAt` como época Unix en milisegundos;
- `version` como versión observada de Claude Code;
- `kind` como tipo de sesión;
- `entrypoint` como origen, por ejemplo `claude-vscode`.

La modificación del archivo representa la última observación disponible. Los
archivos con JSON inválido o sin identificador se omiten para que un registro
dañado no bloquee el resto del inventario.

### Estado conservador

Los registros encontrados usan `agent=claude` y `status=registered`. La presencia
del archivo demuestra que Claude Code registró la sesión, pero no que el PID siga
vivo: puede existir un archivo residual o un PID reutilizado. Comprobar solo el
PID sería insuficiente y añadir una dependencia de procesos no resolvería de
forma portátil esa ambigüedad.

Por ello, estas sesiones:

- aparecen en inventario, filtros e informes de metadatos;
- no cuentan como activas o archivadas;
- no participan en la señal de bloqueo ni en la política de retención;
- no admiten resumen, relevo o digest sin una transcripción real.

### Integración

`scan` y `maintain` aceptan `--claude-source`; por defecto usan `CLAUDE_HOME` o
`%USERPROFILE%/.claude`. La actualización en segundo plano sincroniza Codex y
Claude como agentes independientes, evitando que una fuente elimine registros de
la otra.

Docker Compose monta Claude en `/claude` como solo lectura cuando se define
`CLAUDE_HOME`. Sin esa variable, monta `docker/empty-claude`, de modo que Claude
continúa siendo opcional y el stack mantiene el arranque existente.

El dashboard muestra **Claude Code**, traduce el estado como **Registrada** y
permite filtrarlo expresamente.

### Seguridad y privacidad

- El escáner no modifica los JSON de Claude Code.
- SQLite conserva metadatos normalizados, no el contenido original.
- La API continúa ocultando rutas de archivos fuente.
- El montaje Docker de Claude es de solo lectura.
- No se intenta leer directorios de historial cuya estructura no se haya
  observado con fixtures reales.

### Verificación

- 16 pruebas Python superadas, incluidas fuente ausente, JSON inválido,
  normalización de milisegundos e integración del refresco multiagente.
- 3 pruebas Angular superadas con etiqueta **Claude Code** y estado
  **Registrada**; el filtro se comprobó en la interfaz real.
- Escaneo real de solo lectura: 478 sesiones Codex y 2 registros Claude Code;
  hashes de los JSON Claude sin cambios.
- Build de producción completado y auditoría npm sin vulnerabilidades.
- Imágenes API y dashboard 0.15.0 construidas; Compose validado en loopback con
  ambas fuentes montadas en solo lectura.

### Límites conocidos

- El registro no contiene mensajes, decisiones, tareas ni eventos terminales.
- `registered` no equivale a proceso activo ni a sesión bloqueada.
- El esquema es interno y experimental; los campos desconocidos se ignoran.
- OpenCode sigue pendiente porque no existe una fuente local real para fijar y
  probar su contrato.

## English

### Goal

Add the first real Claude Code source to the shared inventory without claiming
capabilities absent from the available files. This milestone uses local records
observed under `CLAUDE_HOME/sessions/*.json`; it neither invents a transcript
format nor depends on Claude internals.

### Source contract

Each valid JSON file must contain `sessionId`. The adapter also normalizes, when
present:

- `cwd` as repository or working directory;
- `startedAt` as Unix epoch milliseconds;
- `version` as the observed Claude Code version;
- `kind` as the session kind;
- `entrypoint` as the origin, for example `claude-vscode`.

File modification time represents the latest available observation. Invalid JSON
and entries without an identifier are skipped so one damaged record cannot stop
the remaining inventory.

### Conservative status

Discovered records use `agent=claude` and `status=registered`. File presence
proves that Claude Code registered the session, but not that its PID is still
alive: the file may be stale or the PID reused. Checking only the PID would be
insufficient, and a process dependency would not solve that ambiguity portably.

Therefore these sessions:

- appear in inventory, filters, and metadata reports;
- count as neither active nor archived;
- are excluded from blocked signals and retention policy;
- do not support summaries, handoffs, or digests without a real transcript.

### Integration

`scan` and `maintain` accept `--claude-source`, defaulting to `CLAUDE_HOME` or
`%USERPROFILE%/.claude`. Background refresh synchronizes Codex and Claude as
independent agents so one source cannot delete the other's records.

Docker Compose mounts Claude read-only at `/claude` when `CLAUDE_HOME` is set.
Without it, `docker/empty-claude` is mounted, keeping Claude optional and
preserving the existing stack startup.

The dashboard displays **Claude Code**, translates the status as **Registrada**,
and exposes it as an explicit filter.

### Security and privacy

- The scanner does not modify Claude Code JSON files.
- SQLite stores normalized metadata, not original content.
- The API continues to omit source-file paths.
- The Claude Docker mount is read-only.
- No history directory is inspected without real fixtures defining its shape.

### Verification

- 16 Python tests passed, including absent source, invalid JSON, millisecond
  normalization, and multi-agent refresh integration.
- 3 Angular tests passed with the **Claude Code** label and **Registrada** status;
  the filter was checked in the real interface.
- A read-only real scan found 478 Codex sessions and 2 Claude Code records;
  Claude JSON hashes remained unchanged.
- The production build completed and npm audit reported zero vulnerabilities.
- API and dashboard 0.15.0 images built; Compose was validated on loopback with
  both sources mounted read-only.

### Known limits

- The registry contains no messages, decisions, tasks, or terminal events.
- `registered` means neither live process nor blocked session.
- The schema is internal and experimental; unknown fields are ignored.
- OpenCode remains pending because there is no real local source from which to
  define and test its contract.
